## 5. API — Fastify (`apps/api`)

### 5.1 Autentifikatsiya

Barcha `Mini App → API` so'rovlari:

1. **Mini App ochilganda** `POST /auth/init` chaqiriladi
2. Server Telegram `initData` ni HMAC-SHA256 bilan tekshiradi
3. Foydalanuvchi topilmasa — avtomatik ro'yxatdan o'tkaziladi
4. JWT token qaytariladi (24 soatlik)
5. Keyingi barcha so'rovlarda `Authorization: Bearer <token>` header

```
POST /auth/init
Body: { initData: string }  ← Telegram.WebApp.initData
Response: { token: string, user: UserDto }
```

### 5.2 Endpoint ro'yxati

#### Shaharlar va yo'nalishlar

```
GET  /cities                     → Barcha shaharlar ro'yxati
GET  /routes/:routeId/stats      → Yo'nalish narx statistikasi
                                   Response: { min, avg, max, hasEnoughData: bool }
GET  /routes/:routeId/drivers/count → Bugungi faol haydovchilar soni
```

#### Buyurtmalar

```
POST   /orders                   → Yangi buyurtma yaratish
GET    /orders                   → Mening buyurtmalarim (faol + tarix)
GET    /orders/:id               → Buyurtma detali (takliflar bilan)
DELETE /orders/:id               → Buyurtmani bekor qilish
PUT    /orders/:id/extend        → 1 soatga uzaytirish (bir marta)
```

**POST /orders — body:**
```ts
{
  routeId:   number
  fromPlace: string
  toPlace:   string
  travelDate: string  // ISO 8601
  seatType:  "FULL" | "PARTIAL"
  seatCount?: number  // PARTIAL bo'lsa
  luggage:   "NONE" | "SMALL" | "LARGE"
  price:     number
  note?:     string
  isUrgent?: boolean
}
```

#### Takliflar

```
GET  /orders/:id/offers          → Buyurtma takliflari (narx bo'yicha o'sish)
POST /orders/:id/offers/:offerId/accept → Taklifni qabul qilish
```

`accept` javobi: `{ driverPhone: string }` — faqat tanlangan haydovchi raqami

#### Sevimli haydovchilar

```
GET    /favorites                → Sevimlilar ro'yxati
POST   /favorites/:driverId      → Sevimliga qo'shish
DELETE /favorites/:driverId      → Sevimlilardan o'chirish
POST   /favorites/:driverId/order → Sevimlidan to'g'ridan buyurtma (orderId body da)
```

#### Reyting

```
POST /orders/:id/rate
Body: { rating: number (1-5), comment?: string }
```

### 5.3 Response formatlar

**Taklif kartasi (OfferDto):**
```ts
{
  id:          number
  price:       number
  driverName:  string
  driverRating: number
  isFavorite:  boolean
}
```

**Buyurtma holati (OrderStatusDto):**
```ts
{
  id:         number
  status:     OrderStatus
  viewCount:  number   // nechta haydovchi ko'rdi (Redis counter)
  offerCount: number
  expiresAt:  string
  isExtended: boolean
}
```

### 6.2 Ro'yxatdan o'tish (`conversations/registration.ts`)

```
/start
  │
  ├─ [allaqachon ro'yxatdan o'tgan] → Bosh menyu
  │
  └─ [yangi] → Registration conversation:
       1. "Xush kelibsiz! Telefon raqamingizni ulashing" 
          → Contact tugmasi (Telegram native)
       2. Raqam olinadi → DB ga saqlash
       3. "Qaysi yo'nalishlarda ishlaysiz?" 
          → Shahar juftliklarini inline tugmalar bilan tanlash
          → Bir nechta marshrut tanlanishi mumkin (✅ belgisi)
          → "Tayyor" tugmasi
       4. Tasdiqlash xabari + bosh menyu
```

### 6.3 Marshrutlar boshqaruvi (`/routes`)

```
/routes
  → Joriy obuna marshrutlari ro'yxati
  → Har birida "❌ O'chirish" tugmasi
  → "➕ Marshrut qo'shish" tugmasi
      → addRoute conversation:
           1. Chiqish shahri tanlash
           2. Borish shahri tanlash
           3. Tasdiqlash → DB ga saqlash
```

### 6.4 "Hozir yo'ldaman" rejimi (`/onroad`)

```
/onroad
  └─ onroad conversation:
       1. "Qaysi yo'nalishda?" → Obuna marshrutlaridan tanlash
       2. "Nechta bo'sh o'rin bor?" → 1–4 tugmalar
       3. Tasdiqlash → DriverOnRoad yaratish
       4. "Hozir yo'ldaman ✅ — /offroad orqali o'chiring"
```

### 6.5 Yangi buyurtma xabari formati

Haydovchiga keladigan xabar:

```
🆕 Yangi buyurtma

📍 Toshkent, Vokzal → Samarqand, Siyob bozor
📅 15-iyun, 09:00
💺 2 ta o'rin | 🧳 Kichik bagaj
💰 Mijoz narxi: 120,000 so'm
⚡️ Tez ketaman!   ← isUrgent bo'lsa

[✅ Rozi bo'laman]  [💬 Narx taklif qilaman]
```

**"Rozi bo'laman"** bosilganda:
- Offer yaratiladi (price = mijoz narxi)
- Tugmalar o'chiriladi: "✅ Taklifingiz yuborildi"

**"Narx taklif qilaman"** bosilganda:
- `ForceReply` bilan narx kiritish so'raladi
- Kiritilgan narx bilan offer yaratiladi

### 6.6 Narx so'rovi xabari

"Javob berish" → narx kiritish → PriceSurvey (source: SURVEY) saqlash

## 7. Background Jobs — BullMQ (`packages/queue`)

### 7.1 Queues ro'yxati

```
orders:notify      ← Yangi buyurtma → haydovchilarga xabar
orders:expiry      ← Buyurtma muddati tekshiruvi (cron)
orders:warn        ← 15 daqiqa qolganda ogohlantirish
price:survey       ← Narx so'rovi yuborish (cron)
price:stats        ← Narx statistikasini yangilash
```

### 7.2 Job detallari

#### `orders:notify`

- **Trigger:** Yangi buyurtma yaratilganda API tomonidan qo'shiladi
- **Vazifa:**
  1. Buyurtma marshrutiga obuna bo'lgan haydovchilar topiladi
  2. Har bir haydovchiga bot orqali xabar yuboriladi
  3. `isUrgent: true` bo'lsa — `isOnRoad` haydovchilarga ham alohida yuboriladi

#### `orders:expiry` (Cron: har 1 daqiqada)

- Hozirdan 15 daqiqa ichida tugaydigan ACTIVE buyurtmalar topiladi
- `isExtended: false` bo'lsa — `orders:warn` job qo'shiladi
- `expiresAt` o'tib ketgan ACTIVE buyurtmalar → `EXPIRED` ga o'tkaziladi
- Taklif bergan haydovchilarga `❌ Buyurtma bekor qilindi` xabari

#### `orders:warn`

- **Trigger:** `orders:expiry` tomonidan
- Yo'lovchiga bot orqali xabar:
  ```
  ⏳ Buyurtmangizga 15 daqiqa qoldi!
  Toshkent → Samarqand (15-iyun, 09:00)

  [🔄 1 soatga uzaytirish]   [Yopsin]
  ```
- Callback handler `PUT /orders/:id/extend` ga ekvivalent

#### `price:survey` (Cron: har kuni ertalab 08:00 UZT)

- Har bir aktiv marshrut uchun:
  - Obuna bo'lgan haydovchilardan tasodifiy 30% tanlash
  - Narx so'rovi xabari yuborish

#### `price:stats` (Cron: har 6 soatda)

- Har bir marshrut uchun oxirgi 30 kun ichidagi `PriceSurvey` yozuvlari asosida:
  - min, max, avg hisoblash
  - Redis ga cache qilish (`route:stats:{routeId}`, TTL: 6 soat)
- Agar ma'lumot nuqtasi < 5 → cache ga `null` saqlash (ko'rsatilmaydi)

## 9. Xavfsizlik

### 9.1 Telegram initData tekshiruvi (Mini App)

```ts
// packages/shared/src/telegram.ts
import { createHmac } from "crypto";

export function verifyInitData(initData: string, botToken: string): boolean {
  const params = new URLSearchParams(initData);
  const hash = params.get("hash");
  params.delete("hash");

  const dataCheckString = [...params.entries()]
    .sort(([a], [b]) => a.localeCompare(b))
    .map(([k, v]) => `${k}=${v}`)
    .join("\n");

  const secretKey = createHmac("sha256", "WebAppData")
    .update(botToken)
    .digest();

  const expectedHash = createHmac("sha256", secretKey)
    .update(dataCheckString)
    .digest("hex");

  return expectedHash === hash;
}
```

### 9.2 JWT

- Algorithm: `HS256`
- Payload: `{ userId, telegramId, role }`
- TTL: 24 soat
- Yangilash: Mini App har ochilganda `/auth/init` qayta chaqiradi

### 9.3 Rate Limiting

| Endpoint | Limit |
|----------|-------|
| `POST /auth/init` | 10 req/min per IP |
| `POST /orders` | 5 req/min per user |
| `POST /orders/:id/offers/:offerId/accept` | 3 req/min per user |
| Bot: narx kiritish | 10 req/min per telegramId |
